# Plugin clean-room V1 evidence

Date: 2026-08-27

## Result

The released dependencies are independently available, but the end-to-end
public workflow is **not yet release-complete**. The released
`lenso-cli 0.4.6` generates a generic `uppercase.tool@1/run` Plugin; the Harness
correctly rejects it because V1 accepts exactly
`lenso.agent.tool-provider@2` with `catalog` and `execute`.

The candidate CLI change fixes that mismatch. A fresh project generated by the
candidate completed the entire Harness lifecycle using registry dependencies
only. This evidence must be rerun from the next published CLI before Plan 005
is marked done.

as one shared version.

## Released CLI reproduction

The CLI was installed into an empty temporary prefix:

```sh
cargo install lenso-cli --version 0.4.6 --locked --root "$TOOLCHAIN"
git init "$PROOF_ROOT"
"$TOOLCHAIN/bin/lenso" plugin new uppercase --repo-root "$PROOF_ROOT"
cd "$PROOF_ROOT/uppercase"
lenso plugin check
lenso plugin dev --operation run --request-json '{"text":"hello"}' --json
lenso plugin pack --json
```

The generated repository contained only `Cargo.toml`, `Cargo.lock`, `README.md`,
`src/lib.rs`, and `wit/world.wit`. The author-vocabulary audit returned no
Module, Manifest-template, Plan, Receipt, Store, Controller, Supervisor, or
Generation terms. `cargo tree` showed `lenso-guest-sdk 0.1.3` from the registry
and no sibling path or Git dependency.

Harness admission failed closed with:

```text
Harness V1 accepts exactly lenso.agent.tool-provider@2 catalog and execute
```

## Candidate CLI lifecycle

The candidate scaffold emits the Harness Tool contract directly. After editing
the generated Tool to uppercase its input:

```text
plugin check: uppercase@0.1.0 passed
plugin dev: HELLO LENSO
plugin pack manifest: sha256:1c8dd4d5b85060adb02765729fcd5a804e67cb1966c09735df34d6e306716c74
plugin pack artifact: sha256:d47eac42cc4a3760f968546a177aee3df0f45f8db6bce2cc0249c025edf7b5fd
Harness add: uppercase@0.1.0 enabled
Harness Tool result: LENSO PLUGIN
```

The source and version were then changed without invoking a separate verify
command:

```text
plugin check: uppercase@0.1.1 passed
plugin dev: v2: HELLO LENSO
plugin pack manifest: sha256:9e2e99e46d4d8f565336c66956ae97c5d5aca5109550aa4d6a6647244d5b0f98
plugin pack artifact: sha256:37e58e217d8d3c2acb5613ba3ce23f4915b07e51e55dee42d50b5b16946c6d61
Harness add: uppercase@0.1.1 enabled
Harness Tool result: v2: LENSO PLUGIN
```

Changing only the package version again from `0.1.1` to `0.1.2` and running
`plugin check` synchronized the root package entry in `Cargo.lock` offline and
passed. No extra Cargo lock-maintenance command was required.

Truncating one byte from `plugin.wasm` caused admission to fail with a digest
mismatch. `uppercase@0.1.1` remained enabled and continued returning the V2
result. Disable retained the release, enable restored it, remove produced
`No plugins.`, and the base App still completed a Turn.

## Remaining gate

Publish the corrected CLI through the normal release process, install that
exact public version into a new empty prefix, and repeat this document without
using a locally built CLI. Until then the public clean-room gate remains
blocked even though the candidate implementation is proven.
